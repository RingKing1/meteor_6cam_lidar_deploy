# XCalib 六相机–激光雷达外参精修计划

## 1. 目标与结论

目标目录：`../raw_data`

目标是在不修改原始数据的前提下，检测并修正车辆长期运行后六个相机相对激光雷达可能出现的轻微姿态偏移。输出应保留原始标定、候选标定、精修标定、量化评估和可视化核对结果。

关键结论：

1. 原始相机外参可以作为初始解，而且应当作为初始解和先验约束。
2. XCalib 的高层 `Matcher.calibrate()` 默认从匹配点直接执行 PnP/RANSAC，不直接接收“初始外参”。
3. XCalib 的 `OneShotSession.set_calibration()` 可以注入已知标定，用于生成几何确认的伪标签；但它不会自动对该外参做局部优化。
4. 因此推荐路线是：原始外参投影核对 → XCalib 跨模态匹配 → 以原始外参为约束筛选对应点 → 从原始姿态出发做有界局部精修 → 留出序列验证。
5. 如果无约束 PnP 的结果与原始外参差异很小且在留出帧上误差更低，可作为候选；如果差异超出门限，不直接自动采用。

图像尺寸与内参规则：

1. 阶段 0–1 只读取 `raw_data` 下已去畸变的原始 1920×1080 图像。
2. 不使用 `scenes` 下可能已经 resize 的图像进行标定，因为 resize 会改变内参。
3. 若后续使用宽高分别为 `W'×H'` 的 resize 图像，必须按 `sx=W'/1920`、`sy=H'/1080` 同步缩放 `fx/cx`、`fy/cy` 和全部 2D 框。
4. 若 resize 还包含裁剪或 letterbox，不能只做整体缩放，必须根据裁剪偏移和有效区域重新映射内参与框坐标。

## 3. 必须先解决的适配问题

### 3.1 相机模型与畸变

相机 JSON 中的 `distortion` 当前为零，但同目录厂商 SN 文本中存在 `K1` 至 `K6` 等畸变参数。必须先确认：

1. 原始 JPG 是否已由采集端去畸变。
2. JSON 中的零畸变是否为部署系统的真实配置。
3. 厂商参数对应的是普通针孔、OpenCV rational 模型还是鱼眼模型。
4. XCalib 标定应使用针孔模型还是需要先将图像重映射为针孔图像。

在该问题确认前，不把 PnP 输出作为最终标定。

### 3.2 外参方向

相机 JSON 中的 4×4 `extrinsic` 初步按“激光雷达坐标 → 相机坐标”处理，但需要通过一帧点云和 2D 框投影验证。验证内容包括：

- 3D 框中心投影后是否落在对应 2D 框内。
- 车辆、行人等动态目标的投影方向是否合理。
- 左右前后相机是否出现镜像或坐标轴反向。

确认方向后再进行批量转换，不能仅凭字段名猜测。

### 3.3 3D 框格式转换

XCalib 需要 `[M, 6]` 的 3D 框，支持轴对齐范围框或中心尺寸框。FocalFormer 的 `boxes_3d` 格式为：

```text
[cls, cx, cy, zc, l, w, h, yaw]
```

它不能直接传入 XCalib。需要生成以下两种数据之一：

1. 推荐：将旋转框投影为包含八个角点的三维轴对齐 AABB，并增加少量安全余量，转为 `[xmin, ymin, zmin, xmax, ymax, zmax]`。
2. 更精确：扩展数据预处理，使点云裁剪直接支持旋转框；这会修改 XCalib 适配层，但能减少相邻目标点云串入。

第一阶段建议使用 AABB 转换，先验证匹配和标定闭环；如果相邻目标干扰明显，再实现旋转框裁剪。

### 3.4 2D 框格式转换

现有 `bbox2d` NPZ 不是 XCalib 直接需要的 `[K, 4]` 像素框。需要按相机拆分为：

```text
[x1, y1, x2, y2]
```

并保留类别、置信度和相机 ID。若现有 2D 框不完整，则使用已有的 `yolov8x.pt` 对六路图像补跑检测，优先选择车辆、骑行者和行人等能与 3D 框互相对应的动态目标。

### 3.5 XCalib 预训练权重域差异

XCalib 公开发布的权重主要基于 A9/UTC 场景。METEOR 车辆相机分辨率、视场角、安装位置和点云外观可能不同，因此不能只凭单次相似度做自动标定。

首轮必须同时使用两个证据：

- XCalib 相似度分数。
- 原始外参下 3D 框中心与 2D 框中心的几何距离。

只有两者一致的匹配才进入标定。

## 5. 分阶段实施

### 阶段 0：环境与冻结基线

1. 在本目录建立独立 Python 环境，或复用已验证的 CUDA PyTorch 环境。
2. 从 `../../XCalib` 以可编辑方式安装：

```bash
pip install -e ../../XCalib
```

3. 验证 XCalib：

```bash
python -c "import xcalib; print(xcalib.__version__)"
```

4. 记录代码版本、XCalib commit、GPU、CUDA、PyTorch 和模型权重版本。
5. 原样备份转换后的初始标定，不覆盖 `raw_data` 中任何文件。

### 阶段 1：建立帧索引

1. 扫描六段序列的六类图像和 PCD。
2. 以文件时间戳为键建立同步帧表。
3. 标记缺帧、重复时间戳、空 PCD、损坏 JPG 和无法读取的标定文件。
4. 为每帧生成全局唯一的 `(scene_id, frame_id, timestamp)`。
5. 首轮只抽样运行，不直接处理全量 17,845 帧。

建议抽样：

- 每段序列均匀抽取 100 帧用于首轮诊断。
- 覆盖静止、低速、会车、近距离行人和不同距离车辆。

### 阶段 2：转换并验证初始标定

1. 将六个相机 JSON 的内参转换为 `CameraIntrinsics`。
2. 将 4×4 外参转换为统一的 NumPy 数组。
3. 解析厂商畸变文本，核对 JSON 零畸变与厂商参数差异。
4. 解析 `lidar2imu_calib.txt`，但第一阶段只输出激光雷达坐标系下的相机外参，不强行修改 IMU 链路。
5. 用原始外参投影 3D 框中心和角点，生成基础误差报告。

每个相机至少统计：

- 2D 中心与投影中心距离的均值、中位数、P90、P95。
- 投影框与 2D 框 IoU。
- 匹配成功率。
- 近距离、中距离、远距离分桶误差。
- 每段序列的误差趋势。

### 阶段 3：准备 2D/3D 检测输入

1. 检查现有 `scenes/<scene>/bbox2d` 是否覆盖全部六段序列。
2. 将 2D 检测按相机拆分为 XCalib 需要的像素框。
3. 将 FocalFormer `boxes_3d` 转为轴对齐 XCalib 3D 框。
4. 过滤类别不确定、点数过少、严重截断、距离过远和几何尺寸异常的目标。
5. 将每帧输入目标数控制在 XCalib 推荐范围内；PyTorch 可处理更多目标，但 TensorRT profile 的默认上限为 32 个 2D 框和 32 个 3D 框。

### 阶段 4：XCalib 小样本诊断

使用 A9 公开权重先在抽样帧上运行：

```python
matcher = Matcher.from_pretrained(
    "crlite",
    site="a9_dataset_r02_s01",
    device="cuda",
)
result = matcher.match(image, point_cloud, bboxes_2d, bboxes_3d, top_k=5)
```

记录：

- 相似度分布。
- Top-1/Top-3 匹配。
- XCalib 匹配与原始外参投影匹配的一致率。
- 不同相机、场景和距离下的稳定性。
- 明显误匹配样本。

阈值不先写死。根据分数分布选择高置信阈值，再进行人工叠加图抽查。

### 阶段 5：生成高置信 2D–3D 对应点

对每个相机独立执行：

1. 获取 XCalib Top-K 相似度。
2. 使用原始外参计算每个 3D 框中心的投影像素位置。
3. 只保留相似度高且投影中心距离较小的候选。
4. 使用匈牙利或贪心分配保证一帧内一对一。
5. 跨帧累积对应点，并记录场景、帧号、距离、类别和置信度。

建议几何门限初始设为 64–100 像素；长焦/后视和远距离目标可根据分辨率与误差分布调整。任何门限调整都必须在报告中说明。

### 阶段 6：候选外参求解

并行保留两类候选。

#### 候选 A：无约束 PnP/RANSAC

使用 XCalib 的 PnP/RANSAC 流程从高置信对应点直接求解。它的作用是诊断：

- 原始外参是否仍接近全局最优。
- 匹配点是否足以独立恢复姿态。
- 是否存在退化视角或错误对应。

该候选只有在与原始外参差异很小、且留出帧误差改善时才考虑采用。

#### 候选 B：从原始姿态出发的局部精修

这是主方案。对每个相机分别最小化高置信对应点的鲁棒重投影误差：

- 使用原始 `R, t` 作为初值。
- 使用 Huber/Soft-L1 降低误匹配影响。
- 优化旋转残差和平移残差。
- 对更新量设置边界。
- 先在单场景内拟合，再扩展到多场景联合。

建议第一轮自动门限：

- 单相机姿态变化不超过 2°。
- 平移变化不超过 3 cm。
- 若候选超出该范围，暂停自动采用，进入人工复核。

如果数据显示偏移确实更大，可在人工确认后放宽至 3° 和 5 cm。

### 阶段 7：留出验证

不能只在用于拟合的帧上评估。建议：

1. 使用前五段相关帧完成阈值选择和候选拟合。
2. 将 `data_20260910_073823` 作为验证序列。
3. 将 `data_20260910_074912` 作为最终留出测试序列。
4. 也可按时间做交叉验证，防止某个场景目标类型单一造成偏差。

比较原始标定、无约束 PnP 和局部精修结果：

- 中位数、P90、P95 重投影误差。
- 匹配成功率。
- 2D IoU。
- 近/中/远距离分桶表现。
- 六段序列之间的一致性。
- 姿态修正量和平移修正量。

自动采用条件建议为：

- 留出测试集整体中位数误差明显下降。
- 任一相机或距离分桶没有显著退化。
- 修正量处于预设轻微偏移范围内。
- 无约束 PnP 与局部精修方向基本一致。
- 叠加图人工抽查无系统性偏差。

### 阶段 8：输出与部署格式

为每个相机输出：

1. 原始 4×4 外参。
2. 精修 4×4 外参。
3. 旋转和平移增量。
4. 内参及畸变模型。
5. 训练/验证/测试误差。
6. 使用帧数、对应点数和剔除原因。
7. 投影叠加图。

如果部署系统需要 IMU/ego 坐标系下的相机外参，则在确认激光雷达到 IMU 标定不变后，按链路重新计算：

```text
T_ego_camera_refined = T_ego_lidar × T_lidar_camera_refined
```

不直接修改 `lidar2imu_calib.txt`。

## 6. 人工复核触发条件

出现以下任一情况时停止自动采用：

- 相机模型无法确认，或厂商畸变参数与零畸变 JSON 冲突。
- 单相机高置信对应点数量不足，或点集中在单一距离/方向。
- XCalib 高置信匹配与原始投影大面积不一致。
- 无约束 PnP 频繁失败或结果不稳定。
- 姿态修正超过 2°，或平移修正超过 3 cm。
- 留出帧误差没有改善，或某些距离分桶明显变差。
- 六个相机同时出现方向相似的大幅修正，这可能意味着激光雷达或 IMU 参考系发生变化，而不是单相机偏移。

## 7. 首轮执行建议

首轮不跑全量数据，建议按以下顺序推进：

1. 每段序列抽样 20 帧，共 120 帧，完成读取和同步检查。
2. 选择一个前视、一个侧视和一个后视相机验证标定转换。
3. 对这 120 帧运行 XCalib 匹配。
4. 生成原始外参投影叠加图和误差统计。
5. 确认相机模型、外参方向、2D 框和 3D 框转换正确。
6. 再把每段抽样扩大到 100 帧。
7. 指标稳定后，再对全量 17,845 帧进行批处理。
